# data/ — dictionary

One folder per session. Raw files are exactly what the instruments wrote
(checksums in each folder's `SHA256SUMS`; verify with
`shasum -a 256 -c SHA256SUMS`). `processed/` is regenerated by
`tools/day1_analysis.py` and should never be edited by hand.

Time base for everything processed: **seconds since the RaceBox session
start**, `t0 = 2026-08-15T14:52:07.440` local (PDT, UTC−7). The RaceBox
clock is GNSS-disciplined and is the reference; the IMU clock is corrected
onto it (see `processed/imu_clock.csv`).

### imu_sd/WIT38.TXT … WIT41.TXT — WT901SDCL-BT50 onboard storage

Binary, despite the `.TXT` name. A new file opens at every power-on and
rolls over at ~12 MB. Frame format (28 bytes, little-endian int16 fields):

```
0x55 0x61 | ax ay az | gx gy gz | roll pitch yaw | YY MM DD HH MN SS ms_lo ms_hi
```

Scales: acceleration = raw/32768 × 16 g; angular rate = raw/32768 ×
2000 deg/s; angle = raw/32768 × 180 deg. Frames arrive at exactly 200 Hz on
the device RTC (5 ms ticks), but the fusion loop updates the accelerometer
at ~104 Hz and the gyro at ~50 Hz, so ~48% of consecutive frames repeat all
values — dedupe (`imu_characterize.py`, `dedupe()` in `day1_analysis.py`,
`ingest_imu(..., dedupe=true)`) before spectra or sample counts. The RTC
runs ~2% slow and its offset re-arms at each power-on; never use it
uncorrected. Axes (ISO 8855, mount verified in-car): X forward, Y left,
Z up; roll rate = gx, pitch rate = gy, yaw rate = gz. The fused
roll/pitch/yaw angles are unusable under sustained lateral acceleration
(6-axis mode, no magnetometer) and are not used.

WIT39 (29.6 min) spans runs 1–4, WIT40 spans runs 5–6; WIT38/WIT41 are
short pre/post fragments. Parsers: `tools/imu_characterize.py` (`parse_flag61`),
`matlab/ingest_imu.m`.

### app_capture/ — quick-look only, not used in analysis

- `20260815145230.txt` — the WITMOTION app's live-BLE export: tab-separated,
  23 columns (time, DeviceName, AccX/Y/Z g, AsX/Y/Z deg/s, AngleX/Y/Z deg,
  HX/Y/Z µT, Q0–Q3, temperature, height, pressure, version, battery).
  Timestamps are phone receive-stamps clumped in ~30 ms bursts; 4–6% of
  samples are lost in transport.
- `AdamWTSDCL(C3EB113884D1).wplay` — the app's replay capture: the same
  28-byte `0x55 0x61` frames with device time, but the app writes stale
  values (47% acc / 74% gyro repeats vs the device's own file).

Both are complementary-lossy views of the same session; the SD file is
the analysis channel.

### notes.md

Session configuration (PASM order, powertrain/PSM state, cold and hot
pressures, fuel), run table, gate calibration, and the driver's recalled
impressions, with dates and provenance for each statement.

### processed/ — generated

All CSVs are plain comma-separated with a header row; `t_s` is seconds
since RaceBox `t0`.

| file | one row per | columns |
|---|---|---|
| `runs.csv` | run | `run`, `pasm_mode`, `start_time_local`, `t_start_s`, `t_finish_s` (gate crossings), `run_time_s`, `vmax_mph`, `peak_lat_g` (max \|GForceY\| in the moving bout, which includes the terminal braking past the finish), `peak_brake_g` (max −GForceX, same bout), `roll_rate_rms_dps` (IMU gx RMS inside the gates), `roll_rate_per_ay_rate_s` (÷ RMS of d(GForceY)/dt), `roll_gradient_deg_per_g`, `imu_file`, `imu_clock_offset_s` (wall = device + offset at run midpoint), `imu_envelope_xcorr`, `imu_ay_vs_racebox_r` |
| `gates.csv` | gate | `lat_deg`, `lon_deg`, `east_m`, `north_m` (local ENU, origin = session mean position, in `summary.json`), `course_dir_east/north` (unit vector along the course), `calibration_shift_m` (applied along the course: start +2, finish −23), `half_width_m` (12; crossings farther cross-track are ignored) |
| `imu_clock.csv` | clock anchor | `imu_file`, `run`, `t_mid_s`, `offset_s` (best envelope-correlation offset), `envelope_xcorr`, `fit_intercept_s`, `fit_slope` (per-file linear fit offset(t) = intercept + slope·t) |
| `runN_racebox.csv` | RaceBox sample, gates −3 s … +6 s | `t_s`, `time_local`, `lat_deg`, `lon_deg`, `east_m`, `north_m`, `speed_mps`, `a_long_g`, `a_lat_g`, `yaw_rate_dps` (RaceBox native signs, above), `a_lat_kin_g` (= speed × yaw rate / g, the roll-free lateral acceleration), `in_gates` (1 between the start and finish crossings) |
| `runN_imu.csv` | deduped IMU frame, same window | `t_s` (clock-corrected), `ax_g`, `ay_g`, `az_g`, `roll_rate_dps`, `pitch_rate_dps`, `yaw_rate_dps` (ISO 8855: X forward, Y left, Z up), `in_gates` |
| `roll_gradient_samples.csv` | quasi-steady sample | `run`, `pasm_mode`, `t_s`, `a_lat_kin_g`, `roll_angle_deg` (= (a_lat − a_lat_kin) in degrees) — the points behind FIG 06 |
| `summary.json` | – | session metadata, gate calibration, mode means for every metric, grip ceiling raw and roll-corrected, clock fits, the quasi-steady mask, with a one-line definition of each |
